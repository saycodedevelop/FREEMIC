# ลดและตรวจความหน่วง

ความหน่วงของเสียงไมค์มีทั้งช่วงรับเสียงในมือถือไมค์ การรวมแพ็กเก็ต 5 ms เครือข่าย บัฟเฟอร์รับ และระบบเสียงขาออกของเครื่องเล่น การใช้ลำโพงมือถือเองตัดปัจจัย Bluetooth แต่ยังเหลือส่วนอื่น การสร้าง hotspot อาจช่วยเรื่องเส้นทางและสัญญาณแปรปรวน ไม่รับประกันว่าดีเลย์จะลดลงในทุกรุ่น

## ลองกับ Samsung A56 → vivo V29

1. บน vivo เปิดโหมดเครื่องเล่น แล้วเลือก **ตั้งค่าเสียง → Wi-Fi hotspot จากเครื่องเล่น → สร้าง Wi-Fi จากเครื่องเล่น**
2. อนุญาตอุปกรณ์ใกล้เคียง บน Android รุ่นเก่าต้องอนุญาตตำแหน่งแบบแม่นยำและเปิดบริการตำแหน่งด้วย
3. บน Samsung A56 เปิดการตั้งค่า Wi-Fi แล้วกดปุ่มสแกน QR จาก vivo หรือเลือกชื่อและใส่รหัสผ่านที่แสดงด้วยตนเอง ยืนยันให้คงการเชื่อมต่อหากระบบบอกว่าไม่มีอินเทอร์เน็ต
4. กลับเข้าแอปบน A56 และเลือก vivo จากรายการ ถ้าไม่พบ ให้ใช้ IP ของ vivo ที่แสดงในหน้าช่วยเชื่อมต่อ
5. เปิด **โหมดหน่วงต่ำ** บน vivo ใช้ลำโพงมือถือก่อน ตั้ง **ดีเลย์เพิ่ม = 0** และปิด echo/reverb บน A56
6. เปรียบเทียบกับ Wi-Fi บ้านโดยใช้เสียงพูดเดิม ระยะและระดับเสียงเดิม แล้วลองปิดโหมดหน่วงต่ำเพื่อเปรียบเทียบความนิ่ง

hotspot ในแอปไม่แชร์อินเทอร์เน็ต เพลงออนไลน์บน vivo อาจต้องใช้เน็ตมือถือ และบางรุ่นอาจปิด Wi-Fi เดิม ถ้าต้องการแชร์เน็ตหรือกำหนด 5 GHz ให้ใช้ปุ่ม **เปิดการตั้งค่า hotspot ของระบบ** แทน แอปไม่ปิด hotspot ที่ผู้ใช้เปิดจากระบบเอง

บริการเครื่องเล่นคงการเชื่อมต่อไมค์และ hotspot เมื่อปิดจอ สลับแอป หรือ Activity ถูกทำลาย ปิดเมื่อกดหยุด hotspot ยืนยันกลับหน้าแรก เปลี่ยนเป็นเครื่องไมค์ หรือกดหยุดเครื่องเล่นในการแจ้งเตือน เพลงเว็บยังขึ้นกับนโยบายเว็บ และข้อจำกัดผู้ผลิตต้องทดสอบบนอุปกรณ์จริง

## โหมดหน่วงต่ำ

| รายการ | หน่วงต่ำ (ค่าเริ่มต้น) | เสถียร |
|---|---|---|
| บัฟเฟอร์รับเริ่มต้น | 15 ms | 30 ms |
| ขาออก Oboe | 2 bursts | 4 bursts |
| ขนาด callback ใหญ่ / jitter | เพิ่ม reserve ตามความจำเป็น | เพิ่ม reserve ตามความจำเป็น |
| เหมาะกับ | hotspot หรือ Wi-Fi ใกล้และนิ่ง | Wi-Fi ที่กระตุกหรือเครื่องที่เสียงสะดุด |

ตัวเลขเป็นการตั้งบัฟเฟอร์ ไม่ใช่ผลวัดจากปากถึงลำโพง ฮาร์ดแวร์/driver สามารถเพิ่มความหน่วงได้อีก โหมดหน่วงต่ำใช้ Usage::Game สำหรับเสียงไมค์ที่เครื่องเล่น และยังใช้ Android system mixer รวมเพลงเช่นเดิม

ไมค์ผูก control/discovery sockets และ native audio UDP กับเครือข่าย Wi-Fi ที่พบ โดยไม่บังคับ WebView ให้ใช้เครือข่ายไม่มีอินเทอร์เน็ต หากเปลี่ยน Wi-Fi ให้กลับเข้าแอปและเชื่อมต่อใหม่เพื่อเลือก network handle ใหม่

## ถ้ายังหน่วง

- ปิด echo/reverb และตรวจดีเลย์เพิ่มก่อน เพราะเอฟเฟกต์อาจฟังเหมือนความหน่วง
- ใช้ Wi-Fi ไม่แออัด วางเครื่องใกล้กัน ลอง 5 GHz ใน hotspot ของระบบถ้ารองรับ เปรียบเทียบผลจริงกับ Wi-Fi เดิม
- ระหว่างทดสอบลองเปิดหน้าจอไมค์ไว้ และเทียบผลเมื่อปิดโหมดประหยัดแบตเตอรี่
- ทดสอบสาย/USB หากต้องใช้ลำโพงภายนอก แยกผล Bluetooth ออกจากผลลำโพงมือถือ
- ถ้าเสียงสะดุด ให้ปิดโหมดหน่วงต่ำ การลดบัฟเฟอร์ต่อไปเรื่อย ๆ อาจทำให้เสียงขาด
- บันทึกรุ่น Android, RTT, queue, underruns, วิธีเชื่อมต่อและความรู้สึกช้าประมาณกี่ ms หากต้องการตัวเลขความหน่วงจริงต้องวัดสัญญาณเสียงแบบ loopback/การบันทึกอ้างอิง ค่า RTT/2 ไม่ใช่ผลวัดนี้

## การตรวจสอบอัตโนมัติและแหล่งอ้างอิง

การจำลอง native ครอบคลุมโหมดเสถียรและหน่วงต่ำ เครือข่ายนิ่งและ jitter, clock drift ±1500 ppm, callback เล็กและใหญ่ โหมดเสถียรและหน่วงต่ำบนเครือข่ายนิ่งต้องไม่มี underrun ในแบบจำลอง ส่วน stress ของโหมดหน่วงต่ำยอมให้มีการชดเชยสั้น ๆ ไม่เกิน 0.2% ของแพ็กเก็ต โดยไม่เกิดช่วงเงียบต่อเนื่อง การทดสอบนี้ไม่ใช่ผลรับรองบน A56/V29 จริง

- [Oboe low latency และ double buffering](https://developer.android.com/games/sdk/oboe/low-latency-audio)
